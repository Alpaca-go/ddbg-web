# 核心盒性能与全量回归

## 构建体积

同一台 Windows 机器、同一组卡牌数据与生产构建配置。单位为构建输出的十进制 kB；美术缓存不计入 JS。

| 项目         |             优化前 |       优化后 |
| ------------ | -----------------: | -----------: |
| JS 总量      |       10,842.66 kB |  6,764.83 kB |
| JS gzip 总量 |       约 817.92 kB | 约 659.11 kB |
| 应用代码     |   与全部数据同文件 |  1,804.00 kB |
| 共享规则目录 | 多个目录重复序列化 |  4,644.54 kB |
| 第三方库     |       与应用同文件 |    315.71 kB |

`battleDataPlugin` 仅在生产构建时按完整 JSON 内容共享四份目录中的相同条目；不按卡号合并，不更改历史数值、数组顺序和存档协议。开发服务器和 SSR 保留原有目录输出。四份真实目录有逐项一致性回归。

JS 总量减少约 37.6%，gzip 总量减少约 19.4%。拆分后的规则目录和第三方库可在应用代码更新时复用缓存，但首次进入仍要加载所需规则数据。大包警告尚未消除，不以拆文件冒充首次下载减少。

构建产物可独立冒烟：

```powershell
pnpm build
pnpm --filter @ddbg/web exec playwright test --config playwright.preview.config.ts
```

preview 使用 8081，与开发服务器分离；复用首页和初始威胁的三条 UI 冒烟，验证 Stygian 开局、页面交互和保存/刷新/加载。

## 存档性能样本

```powershell
pnpm --filter @ddbg/web exec vite build --config vite.save-profile.config.ts
$env:DDBG_PROFILE_MAX_LOG='1'
node .cache/quest-save-profile/profile.mjs
```

使用现有种子 2、既有自然策略及真实单任务日志，记录战斗中检查点及离场之前的状态。默认比较真实战斗、约 200 条真实任务命令，以及补齐到 1,000 条的合法 ping 日志；设置 `DDBG_PROFILE_MAX_LOG=1` 另测 5,000/10,000 条。探针单独构建后直接由 Node 执行，计时不经过 Vitest 的模块加载器。

ping 扩展只用于测量日志长度开销，不能代表同长度实战耗时，也不构成 II/III 全战役验收。样本使用完整测试目录，不能把它的体积或耗时直接当作正式页面的长战役读档表现。计时包含保存时的严格重放与 JSON 编解码，不含浏览器 localStorage 或配额不足时的 gzip 存储耗时。

本机 Node 24.21.0，在全量单测与浏览器回归均未运行时测得。每项先预热 1 次，再采样 3 次，表内为均值：

| 命令数             | JSON 字节数 |  保存及编码 | 解码及严格加载 |
| ------------------ | ----------: | ----------: | -------------: |
| 129 条真实战斗前缀 |  10,926,831 |  1,398.9 ms |     1,247.4 ms |
| 200 条真实任务前缀 |   5,578,090 |    917.4 ms |       836.9 ms |
| 扩展至 1,000 条    |   5,622,889 |  1,759.3 ms |     1,679.1 ms |
| 扩展至 5,000 条    |   5,846,889 |  6,148.2 ms |     6,074.3 ms |
| 扩展至 10,000 条   |   6,126,889 | 11,842.4 ms |    11,789.4 ms |

保存/读取仍在页面主线程同步回放，长日志存在可感知的阻塞风险。本轮没有改变严格校验协议；把回放移到 Worker 或减少重复校验属于后续优化。真正完整长战役仍缺实档样本，不能用这些压力数据替代玩家链验收。

## 回归边界

Vitest 默认设为 2 workers、30 秒通用预算，与本轮全量命令一致；场景已有的 20/120/240 秒等显式预算不变。此前将全量单测与浏览器并跑时可用内存降至约 1.7 GB，出现了可在空闲环境消失的超时，最终验证分开执行。

首轮完整 Playwright 出现 Necromancer 存档用例的 worker 堆达到约 4 GB、退出码 134，新 worker 重试通过。SSR 测试现通过文件专属的 worker-scoped option 隔离进程，文件结束后回收其模块图与夹具；未提高堆上限、未删断言。截图只写 Playwright 的测试输出目录，避免自动覆盖文档里的人工验收图。

- R-190：不调整种子、玩家策略、游戏数值以制造胜利。
- R-214 / R-215：旧选招和抗性断言随已核准卡面修正。
- R-204：Necromancer II 的胜利夹具须同时清理首场 Boss 战中的 Bone Captain，不能只标记 Boss 阵亡。
- 固定最暗路线若全灭，严格检查真实停点和存档防篡改；不能把全灭误报为命令拒绝，也不能伪造最终战胜利。原胜利路径断言仍保留。
- seed6 的实际回村状态仍是四人存活、各 2 XP、60 金，但首日看守人封锁 Guild。出征/准入测试改用同命令序列的通用回村前缀，不再误要求 Guild 开放；公会服务测试保留原有严格前置。II 级准入仍有明示等级夹具，真实 II/III 玩家链另行验收。
- seed6 的实际候选是 p010/p006，原 p008/p007 黄金值已过时。自然抽牌检查实际结果；p007/p008 特定出征、弃牌和奖励边界使用明示候选夹具，重放从该选择点起算，不改自然路线的 RNG 或声称自然抽到了指定任务。
- Q-162 保持 skip；不扩大 R-201 最终战自动化验收边界。

## 验证结果

- Node 24.21.0、pnpm 12.9.1；本机通过临时将 `.cache/node-24.21.0` 放在 PATH 首位运行。
- 全量 Vitest：479 文件通过，3,657 测通过，1 测按 Q-162 跳过；共 3,658 测，用时约 23 分钟。
- typecheck、lint、生产 build 通过。构建体积以同版本的最终产物为准。
- 构建产物 preview 冒烟：3 条通过（16.7 秒）。初始威胁的正式网页存档从发起点击到完成提示为 455 ms，加载到结果可见为 419 ms；包含浏览器存储与自动化等待，只是单条短日志的一次端到端观测，不代表长战役或纯引擎耗时。
- 隔离后的完整 Playwright：55 条通过、1 条按 Q-162 跳过，用时 16.5 分钟；没有失败、重试或 worker OOM。
