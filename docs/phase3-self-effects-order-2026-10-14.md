# Phase 3：英雄自身效果先于目标结算

依据核心 R20 与 R-069，单目标／多目标技能共享声明快照与原技能骰：先结算掷骰被动、自身治疗／创伤／状态／光照及自身 Shuffle，完成其压力追加伤口、死门、意志或心脏病后，存活者才结算目标伤害、反击及目标效果。死亡取消尚未提交的攻击，不把目标伤害回滚来伪造顺序。

自身位移待选期间仅保留自身意图，目标生命不变。区域／Balanced 选择完成后续接剩余效果；目标自己的位移仍可另有待选。声明时的姿态、Buff 和光照决定原骰的命中判定，不因自身移动重新校验技能可用姿态／射程或重掷骰；暴击同区名单、目标效果时光照与生命使用自身结算后的状态。自身治疗、创伤和状态不重复支付，缺意志资料时保留已确认骰及未完成选择，补回资料后继续。

`ownPending` 标记的事件是已确定骰面及待结算目标的预览，消息明确“目标效果尚未提交”；最终技能事件只在目标效果真正提交时发出，行动／死亡／胜利只收尾一次。旧测试在自身分岔前假定目标已经受伤／死亡的断言改为验证延后提交。此步骤也解除空区域自身 Vertigo 追加伤口的旧停点，因为其后本来没有目标攻击，现有生命→压力收尾可完整处理。

覆盖真实四核心技能、单／多入口的 Bleed Out 自身创伤致死、Point Blank Shot 自身 Vertigo 心脏病死亡（暴击恢复尚未发生）、取消目标伤害／反击／Bleed、Balanced 与区域选择、意志资料拒绝与修复、种子重放；既有无 Life 算法夹具继续使用其投影，不当作真实任务验收。Spiked Pit 与 Vertigo 的跨卡顺序另按 R-072 接入，不在本步开放任何尚未完成的板块。

验证通过：typecheck、lint、917 项全量单元／场景测试、build、全部六条既有 Playwright 冒烟及截图检查。GitHub Actions 的账号付款／支出限制若仍阻止任务启动，则记录精确提交与本机通过结果，按用户既有授权合并，不宣称 Linux CI 通过。
