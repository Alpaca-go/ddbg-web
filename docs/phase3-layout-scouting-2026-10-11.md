## 设计与运行

`pnpm dev` 后访问 `http://localhost:5173/?phase=3`。页面为固定种子 1 的独立侦察沙盒，使用中立英雄、光照 5，从“房间 G 已结算”的注入点开始。这里没有执行进入 G 的探索、房间效果、奖励或任务清理。标准 / Radiant 可以重置。原战斗沙盒仍在 `/`。

- 数据：QuestMap 是探索地图，不能拿已有 `dungeon_tile` / Room Tile 战斗区域代替。新增独立 Zod schema，校验唯一起点、节点 / 边引用、重复、连通性、灰点两段连接与代币种类；布置时严格校验任务代币总数等于房间槽数，不套用 8 / 16 占位补槽（R-046）。
- 引擎：`createDungeonSandbox` 接受地图 / 分布，Fisher–Yates 洗混走已有种子 RNG，记录布置游标；地图固定不另抽地图。状态与输入不被修改。只提供沙盒构造入口，`pending` 标注没有升级为战役可用数据（R-048）。
- 公共命令：`scoutDungeon` 返回全员同意 / 取消的 `PendingChoice`；UI 只呈现引擎选项。取消不扣压力；同意后全员压力 +1，揭示当前房间直接相邻的房间代币。选择 ID 随决定递增，过期选择拒绝（规格书 §5.4，官方 R14）。
- 灰点是一等节点，阻断侦察视线，不能从灰点侦察（R14、R-046）。p1 没有灰点，用明确标注为合成的测试图验证此边界，不把合成图入库为印刷数据。
- `beginDungeonExploration` 返回相邻路线选择；选定后交出 `from / to / dicePerHero`，消费一次侦察减骰标志。标准 2→1，Radiant 1→0（R-013、规格书 §16）；停在 `awaitingHazards`，不掷探索骰、不移动、不翻开目标房间、不做房间结算。原路返回未接线，因此不提供返回起点的路线。
- 每名英雄压力到 10 时已支付侦察压力，进入 `blockedPressure`，不继续揭示或给减骰。探索的意志检定 / 心脏病接线尚未实现，不能静默截断压力。非中立英雄、光照压力修正、生命与战役同步留后续接线，本刀不扩大 Phase 2。
