## 1. 这条线在做什么

把正式流程 UI 改成**正俯视、像真实桌游桌面**，只改 **`apps/web` 表现层**。Kyries 说「UI 最后再改」——意思是页面级大改版可以后调，**切片仍按 S2→…→S11 推进**，不要停工等新设计稿。

| 已定约束（Kyries 拍板）                      | 说明                                                   |
| -------------------------------------------- | ------------------------------------------------------ |
| 正俯视、不倾斜                               | 不要 3D / CSS 透视桌面                                 |
| 固定 4 个玩家位                              | 不按人数伸缩席位                                       |
| 疾病 / 正负怪癖 / 美德 / 苦难牌堆 **不常驻** | 触发时滑出（S6）                                       |
| 布局为网页重设计，**不抄 TTS**               | TTS 只作「桌游感」参考                                 |
| 美术只用印刷稿                               | `.cache/print-card-art`（gitignore）；禁止 TTS / AI 图 |
| R-048                                        | 不自创印刷几何；未核实图标用**中文**占位               |
| U-01（已批）                                 | ≤300ms CSS 过渡；**不加音效**                          |
| 不进 Phase 5                                 |                                                        |
| CI                                           | GitHub Actions 因未充值不可用；**以本机闸门为准**      |

### 五主画面（2026-10-21 拍板）

1. **开局建队**
2. **村庄**：一张桌面；建筑**鼠标悬浮弹出面板**（点击固定 **待确认**）
3. **出征准备**
4. **地牢桌面**：**探索与战斗同一页**；遇敌在桌面上直接展开战斗，打完收回地图
5. **回村结算**：**单独一页**

另有主菜单 / 存档；战役总览并进村庄。

### 实际正式流程（代码现状，与「规划理想顺序」略有差别）

`开局建队 → 出征准备 → 地牢 → 战斗 → 回村结算 → 村庄 → 抽下一任务 → 第二轮地牢`

- 第一轮出征前**不经过**村庄。
- 第二轮选任务在村庄里 `chooseNextQuest`，**不一定**再进出征准备页。
- **待确认**：第二轮及以后是否仍应经过出征准备页（流程层，未授权前不要改引擎流程）。

## 4. S2 验收标准（接手后第一刀）

1. `game.battle` 存在时仍在**同一地牢桌面页 / 同一外壳**内，不跳独立战斗页。
2. 中央：姿态轨 + 区域网格可读；1280 宽无横向滚动；卡片不被严重裁切到一词一行（相对 S1 后现状有可感知改善）。
3. 左下：先攻牌堆（背面 + 剩余张数示意）+ 回合轨「第 r / 4 轮」；数值只读引擎，没有的显示「—」，**不编数值**。
4. 正式流程能：探索遇敌 → 进战斗 →（至少）开始行动；现有相关 e2e 通过（可调选择器，不删断言）。
5. `pnpm typecheck` / `lint` / `test` / `build` 本机全绿。
6. PR 描述附 1280 截图：进战前一刻、战斗中至少各一张。
7. 不改 `packages/engine`；不改存档 schema；不动沙盒专用路由除非必要且说明。
