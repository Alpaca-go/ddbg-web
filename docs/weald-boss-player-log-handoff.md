# Weald Boss 玩家日志交接

本说明只使用已有页面与完整命令日志入口，不新增规则、胜利门槛或种子筛选。依据 [开发计划步骤 6](weald-development-plan.md)、[R-190](rulings.md#r-190)。

## 操作与导出

1. 在页面启用 Core 与 Weald，正常选择任务、出征、回村和养成。保留同一份进度，不重新建局替换此前的普通任务历史。
2. 按页面实际抽到的任务、威胁与待选继续操作。Hag／Pounder 的目标、路线、补给、饰品和村庄安排由玩家决定；不要求使用测试种子，也不保证某一输入会胜利。
3. 到达 Boss、遇到问题、战斗结束或回村后，都可以点击“导出存档文件”。最终文件包含初始入口与此前完整命令，不需要手工填写事件或数值。
4. 文件保存在你选择的本地目录。提供文件路径即可；无需截图或修改 JSON。失败、中途待选和胜利日志都可以交接。

## 恢复并继续

- 在首页使用“导入存档文件”选择导出的 JSON；导入会严格重放完整日志，不把文件快照直接当可信状态。
- 若导入成功，可从原来的战斗／待选继续。Hag 释放待选也应保留，选择后不重复此前已结算的捕获或伤口。
- 文件导入不覆盖“本机存档”槽；要更新该槽，另行点击“保存进度”。
- 导入被拒绝时保留原文件和页面已有进度，不编辑种子、快照或命令来绕过校验。可提供该文件路径和错误文字。

## 验收范围

| 提供的日志                                         | 能核对什么                                     | 不能据此宣称什么                  |
| -------------------------------------------------- | ---------------------------------------------- | --------------------------------- |
| 从普通任务开始、包含养成和 Boss 任务的完整同局日志 | 实际普通任务完成、回村、选任务、养成与自然抵达 | 尚未发生的胜利或回村              |
| Boss 任务直接开局或自动 seed6／seed17 回归检查点   | 单任务部署、机制、文件恢复和真实停点           | 跨任务养成、玩家已实测            |
| 战斗失败或中途待选                                 | 规则与状态机、失败路径、恢复续接               | 自然胜利                          |
| 同局 Boss 胜利并完成回村                           | 对应 Boss 的实际胜利、结算与回村               | 另一 Boss、高等级或完整战役已验收 |

Hag 仍需实际跨任务养成抵达与回村；Pounder 仍需实际养成及自然胜利。按 Hag → Pounder → Shrieker 顺序，不用机制夹具或种子搜索替代这些输入。玩家尚未实测时，保留缺口，不修改规则或数值求胜。
