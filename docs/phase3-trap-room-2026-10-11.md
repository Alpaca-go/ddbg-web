# Phase 3：Trap 房间分配与再次进入

前一刀 #111 已合并，基线 main `84f4129`。本刀在 `codex/phase3-trap-room` 接非 Empty 房间的第一个明确类型，不扩展光照、守卫战斗或村庄 / 战役。

## 来源与实现

已从本地官方核心规则书 `C:/Users/kyrie/Desktop/DDBG/DD_EN_COREBOX_RULES.pdf` 读取并对照完整 R15 页图。规则依据：规格书 §5.7（R15）、§8.2（R28）、§9.2（R29），以及 R-005、R-026、R-045、R-048。没有用印刷卡牌补规则或引用 FAQ，无新增卡牌转录 / 图标命名。

- 探索或原路返回进入 Trap 后停在房间，`resolveDungeonRoom` 开启英雄选择和分配 PendingChoice。每名英雄选总计 DL 点的伤口 / 压力，DL 1 / 2 / 3 各有 2 / 3 / 4 种组合；选择英雄时不支付数值。
- 每名英雄有自己的分配选择，已完成者从英雄选项移除；每人只支付一次，陈旧选择和重新开始拒绝。全部完成前侦察 / 导航被冻结。
- Trap 是 Wound，不是攻击（R-026）；不掷命中骰、不吃 Protection / 攻击伤害修正。Tool 没有抵消选项（R-045），补给和金币不变。
- 纯伤口用既有种子化生命接口：首次到死门不掷骰，再受任何正数伤口只掷一次；死亡停在已到达的房间，等待替换，不发战役结果。
- 纯压力到 10 接完整有限意志牌堆；压力与已完成英雄先记录，缺资料可补齐后恢复，不重新扣数值 / 重掷。恢复后回到未分配英雄列表，不揭示邻居，不触发侦察或战斗回合效果；心脏病停在替换接口。
- 全部完成后恢复导航，但从不清除 Trap 代币。通过已走过的普通走廊返回再次进入同房间，重建本次分配记录，重新支付。修正网页停点文字：房间结算时队伍已经到达，而不是“尚未移动”。

## 演示

`pnpm dev` → `/?phase=3` → p1 →「Trap 房间（种子 1、DL 3、hero-0 压力 8）」→ 重置 Radiant → 侦察并同意 → 选 D → 掷探索骰。

此例固定 DL 3 / 光照 5 / 英雄属性和压力为沙盒注入，任务分布和种子不变；种子 1 真正给 D 分到 Trap。Radiant 侦察后每人零骰，房间分布洗牌游标为 7，不强制骰面。hero-0 压力 9 后选择纯压力 3，完成一次意志检定；其余可分别选 1 伤口 / 2 压力、3 伤口 / 0 压力、0 伤口 / 3 压力。随后 D → G → D 按 R14 各加一压力，再次完成四人纯伤口分配，D 仍显示陷阱。

## 已知边界与下一步

同一次混合分配遇到已在死门或压力到 10 的复合顺序，已记 Q-64；该组合在任何支付 / RNG 前整次拒绝，可改选纯分配。未猜测死亡后另一部分如何支付。死亡后的英雄替换、完整被动系统与任务结果仍留给后续接口。其他 Q-52、Q-59–63、光照 / 探索陷阱缩放边界保持。

Phase 3 仍未完成任意任务闭环：Dark / Curio / Lair / Treasure / Objective 房间、柴火休息、撤离与任务 / XP 仍待接。下一候选是普通守卫房间战斗入口：先从本地资料库核对完整房间卡牌池及获批 Room Tile 关联，再对接既有遭遇战；Dark 房间需沿用光照确认停点。
