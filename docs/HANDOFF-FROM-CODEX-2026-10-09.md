## 已接通

`createBattleState(seed, setup)` 接收调用方提供的已核实卡牌、实体、区域邻接与高低地、光照。它复制初始数据，拒绝重复 ID、非法区域关系、非法生命 / 压力等输入。

`applyCommand` 支持 `playHeroSkill`（使用者、技能、单个目标、可选正反面与方向）和 `resolveChoice`（选择 ID、选项 ID）。使用者必须装备该技能；从状态推导姿态、区域最短距离、Guard、同区英雄名单，调用现有 `resolveHeroSkill`。

- 伤口、压力、怪物死亡标记、清除已有 Bleed / Blight、形态写回新状态；同一个实体的自身与目标结果合并。
- 卡面明确的 Push / Pull 存为 `shuffleIntents`，保留被位移者及参照对象，不移动棋子与姿态轨。
- `Push N or Pull N` 沿用纯函数的解析器返回 `PendingChoice`；等待时其他命令拒绝，过期选择拒绝。
- 掷骰来自种子与 `rngCursor`。拒绝和待选不消耗 RNG，无 Acc 的自身效果不消耗 RNG。事件记录骰面、结算结果与跳过项。
- 原有 `ping` 探针保持兼容。

依据：核心规则说明书 §6.5（R19–21）、§6.7–6.9（R21、R25），裁定 R-020、R-021、R-024、R-031、R-048。没有引入新的规则裁定或卡牌数值。

## 块 B：普通遭遇战先攻与回合接线

块 A 已于 Kyries 授权后本地提交为 `f619b70`。随后推进块 B，在 `codex/phase2-initiative-turns` 分支上继承块 A 提交，尚未推送或合并。

- `startBattle` 校验 4 名存活英雄、双方姿态占格，建立普通遭遇战第 1 轮。怪物须提供已核实的 `stanceSlots`（1 或 2）和姿态；大型怪仍只放 1 张普通怪物先攻卡。
- `drawInitiative` 抽阵营卡，在抽牌时按当前姿态挑选本轮未行动的角色（R-032）；无可行动者则弃卡继续抽。
- 先攻洗牌和技能骰共享种子 / RNG 游标。每轮只重建存活角色的牌堆，第 4 轮结束仍有怪物时记录撤退（R17、R25）。
- 英雄有 2 个行动：现阶段接通技能与 `changeStance`。换姿态和相邻英雄互换，只改轨道；成功技能本回合不能重用，落空可以重用但仍消耗行动（R18–19、R-025）。拒绝或等待方向选择均不消耗行动。
- 普通怪物通过沙盒命令 `finishMonsterTurn` 手动确认回合边界；这个命令不执行怪物技能、移动或 AI。
- 怪物死亡后按占格数补姿态位，棋子区域不动（R-030）；最后一只怪物死亡立即结束战斗。

现阶段只支持普通遭遇战，未实现 Boss / 多行动怪物。Move、Interact、召唤、战利品 / 房间奖励与战斗清理、英雄死亡 / 替补、状态代币、苦难 / 美德仍未接入。`BattleEntity` 的现有状态标识与布尔值没有持续时间或来源：有 Bleed / Blight / Buff / Debuff / Mark / Guard / Protection / Riposte，或英雄压力 10 时，回合流程拒绝启动 / 抽牌，不跳过回合开始结算。Protection 目前无法区分内置与代币，保守地一起拒绝。纯技能沙盒仍可使用原有结算。

实际位移仍未接入；生成 `shuffleIntents` 后禁止继续遭遇战操作，防止使用过期位置继续行动。R-048 的 null 数值 / duration 没有新增默认值。

依据：说明书 §6.1–6.5、§6.11–6.12（R16–19、R24–25），裁定 R-025、R-030、R-032、R-048。新增 11 项场景测试，包含完整四轮命令回放、共同 RNG 序列、换姿态后再抽牌、落空 / 成功重用、无 Acc、死亡弃牌、大型怪补位、方向待选的行动计数和位移阻塞。

块 B 验证：typecheck、lint、150 项 Vitest、build 通过；使用相同本机 Chrome 临时配置运行原有首页冒烟，1 项通过。
